## 1. Пользователи (Users)

### POST `/api/users`
Регистрация нового участника системы.

**Тело запроса:**
```json
{
  "name": "Иван Иванов",
  "email": "ivan@test.ru",
  "password": "secure_password",
  "role": "Customer"
}
```
*Доступные роли:* `Customer`, `Carrier`, `Admin`, `Support`.

**Пример ответа (201 Created):**
```json
{
  "id": 1,
  "name": "Иван Иванов",
  "email": "ivan@test.ru",
  "role": "Customer",
  "rating": null,
  "completedOrders": null
}
```

### PUT `/api/users/{id}`
Обновление данных пользователя. Доступно только администраторам.

**Параметры запроса (Query Parameters):**
- `name` (string) — Новое имя.
- `email` (string) — Новый email.
- `role` (enum) — Новая роль.
- `adminId` (long) — ID администратора, выполняющего действие.

### DELETE `/api/users/{id}`
Удаление пользователя. Доступно только администраторам.
*Примечание:* Невозможно удалить пользователя, у которого есть активные заказы (со статусами NEW, ASSIGNED или IN_PROGRESS).

### GET `/api/users/admin/stats`
Получение сводной статистики по всей системе (количество пользователей, заказов, активных и завершенных сделок).

## 3. Заказы (Orders)

### POST `/api/orders`
Создание заявки на перевозку груза.

**Тело запроса:**
```json
{
  "customerId": 1,
  "fromCity": "Москва",
  "fromAddress": "ул. Ленина, д. 15, склад 3",
  "toCity": "Санкт-Петербург",
  "toAddress": "Невский пр., д. 100, офис 405",
  "weight": 5.5,
  "deadline": "2024-12-20T18:00:00",
  "categoryId": 2
}
```
*Примечание:* `categoryId` является опциональным, но рекомендуется для точного подбора транспорта.

### PUT `/api/orders/{id}/confirm`
Перевозчик подтверждает, что он принял назначенный заказ и приступает к работе.

**Параметры запроса:**
- `id` (path) — ID заказа.
- `carrierId` (long, query, **обязательный**) — ID перевозчика, которому назначен заказ.

**Пример запроса:** `PUT /api/orders/6/confirm?carrierId=18`

*Примечание:* Переводит заказ из статуса `ASSIGNED` в `IN_PROGRESS`. Система проверяет, что `carrierId` совпадает с назначенным перевозчиком, что предотвращает перехват заказов.

### PUT `/api/orders/{id}/complete`
Перевозчик отмечает, что доставка успешно завершена.

**Параметры запроса:**
- `id` (path) — ID заказа.
- `carrierId` (long, query, **обязательный**) — ID перевозчика, выполняющего доставку.

**Пример запроса:** `PUT /api/orders/6/complete?carrierId=18`

*Примечание:* Переводит заказ из статуса `IN_PROGRESS` в `COMPLETED`. У перевозчика автоматически увеличивается счетчик `completedOrders`.

### GET `/api/orders/search`
Поиск заказов перевозчиками.

**Параметры запроса (Query Parameters):**
- `fromCity`, `toCity` (string, опционально)
- `minWeight`, `maxWeight` (number, опционально)
- `urgent` (boolean, опционально) — фильтр срочных заказов (дедлайн менее 3 дней).
- `categoryId` (long, опционально) — фильтр по типу груза.

### PUT `/api/orders/{id}/cancel`
Отмена заказа. Доступно Customer и Admin. Нельзя отменить заказ, если он уже имеет статус `COMPLETED`.

### PUT `/api/orders/{id}`
Обновление данных заказа. Доступно только администраторам.
*Примечание:* Невозможно изменить заказ, который уже имеет статус `COMPLETED`.

### DELETE `/api/orders/{id}`
Удаление заказа. Доступно только администраторам.
*Примечание:* Невозможно удалить заказ, находящийся в процессе выполнения (`IN_PROGRESS`) или завершенный (`COMPLETED`). При удалении автоматически удаляются все связанные предложения (Bids).

## 4. Перевозчики (Carriers)

### GET `/api/carriers/search`
Инструмент для заказчиков по поиску надежных исполнителей.

**Параметры запроса (Query Parameters):**
- `minRating` (number, опционально) — минимальный рейтинг (0.0 - 5.0).
- `minCompletedOrders` (integer, опционально) — минимальное количество выполненных заказов.

*Примечание:* Результаты автоматически сортируются по убыванию рейтинга и опыта.

## 5. Предложения (Bids)

### POST `/api/bids`
Перевозчик оставляет коммерческое предложение по конкретному заказу.

**Тело запроса:**
```json
{
  "orderId": 1,
  "carrierId": 2,
  "price": 15000.00,
  "estimatedDays": 1,
  "comment": "Готов забрать груз завтра утром"
}
```

### GET `/api/bids/orders/recommendations`
Ключевой аналитический эндпоинт. Возвращает список предложений для заказа, ранжированных алгоритмом оценки рисков.

**Параметры запроса:** `orderId` (long, query).

**Пример ответа:**
```json
[
  {
    "bid": {
      "id": 2,
      "price": 35000.00,
      "estimatedDays": 3,
      "status": "PENDING",
      "carrier": {
        "name": "Иван Надежный",
        "rating": 4.8,
        "completedOrders": 120
      }
    },
    "smartScore": 51.9,
    "recommendation": "Оптимальный выбор: высокая надежность, низкий риск срыва срока",
    "delayRiskPercent": 10.0
  }
]
```

### PUT `/api/bids/{bidId}/accept`
Заказчик выбирает предложение.
*Примечание:* Статус заказа меняется на `ASSIGNED`. Выбранное предложение получает статус `ACCEPTED`, все остальные предложения по этому заказу автоматически получают статус `REJECTED`.

### PUT `/api/bids/{bidId}/reject`
Заказчик вручную отклоняет конкретное предложение. Предложение получает статус `REJECTED`.

## 6. Отзывы (Reviews)

### POST `/api/reviews`
Оставление обратной связи после успешного завершения заказа.

**Параметры запроса (Query Parameters):**
- `orderId` (long) — ID завершенного заказа.
- `customerId` (long) — ID заказчика.
- `rating` (integer) — оценка от 1 до 5.
- `comment` (string, опционально) — текстовый отзыв.

*Примечание:* После сохранения отзыва система автоматически пересчитывает средний рейтинг перевозчика на основе всех его оценок.

## 7. Техническая поддержка и Чат (Support)

### POST `/api/support/tickets`
Создание обращения в службу поддержки.

**Параметры запроса (Query Parameters):**
- `authorId` (long, обязательный) — ID пользователя (Customer или Carrier).
- `subject` (string, обязательный) — Тема обращения.
- `description` (string, обязательный) — Описание проблемы.
- `priority` (string, опциональный, по умолчанию "MEDIUM") — `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`.
- `relatedOrderId` (long, опциональный) — ID заказа, с которым связана проблема.

### POST `/api/support/tickets/{id}/messages`
Отправка сообщения в чат тикета (поддерживает вложения).

**Формат запроса:** `multipart/form-data`
**Параметры:**
- `authorId` (long, обязательный)
- `message` (string, обязательный)
- `isInternalNote` (boolean, опциональный) — `true`, если это внутренняя заметка поддержки (не видна клиенту).
- `attachments` (file[], опциональный) — Список файлов (скриншоты, документы). Максимальный размер файла: 10MB.

### GET `/api/support/tickets/{id}/messages`
Получение полной истории переписки по тикету (отсортировано по времени создания).

### PUT `/api/support/tickets/{id}/mark-read`
Отметить все сообщения в тикете как прочитанные от имени пользователя.
**Параметры:** `userId` (long, query).

### GET `/api/support/unread-count`
Получение общего количества непрочитанных сообщений поддержки для конкретного пользователя.
**Параметры:** `userId` (long, query).

### PUT `/api/support/tickets/{id}/assign`
Назначить тикет на конкретного сотрудника поддержки.
**Параметры:** `supportId` (long, query).

### PUT `/api/support/tickets/{id}/resolve`
Отметить тикет как решенный. Доступно только ролям `Support` и `Admin`.

### PUT `/api/support/tickets/{id}/close`
Закрыть тикет (терминальный статус). Доступно только ролям `Support` и `Admin`.

## 8. История и аналитика

### GET `/api/orders/customer/{customerId}/history`
Возвращает архив заказов заказчика (статусы `COMPLETED` и `CANCELLED`), отсортированный по дате дедлайна.

### GET `/api/orders/carrier/{carrierId}/history`
Возвращает архив заказов перевозчика (статусы `COMPLETED` и `CANCELLED`).

### GET `/api/orders/customer/{customerId}/active`
Возвращает активные заказы заказчика (статусы `NEW`, `ASSIGNED` и `IN_PROGRESS`), отсортированные по срочности.

### GET `/api/orders/carrier/{carrierId}/active`
Возвращает активные заказы перевозчика (статусы `ASSIGNED` и `IN_PROGRESS`).

### GET `/api/orders/customer/{customerId}/stats`
Возвращает сводную статистику по деятельности заказчика (общее количество, завершенные, активные, отмененные, общая сумма, средний чек).

### GET `/api/orders/carrier/{carrierId}/stats`
Возвращает сводную статистику по деятельности перевозчика (поле `totalSpent` в данном контексте означает общий заработок).

## Жизненный цикл заказа

```
[1] СОЗДАНИЕ
    │
    ▼
┌──────────┐
│   NEW    │  Заказчик создает заказ
└────┬─────┘  (POST /api/orders)
     │
     │ Перевозчики оставляют предложения (POST /api/bids)
     │ Заказчик выбирает лучшее (PUT /api/bids/{id}/accept)
     │
     ▼
┌──────────┐
│ ASSIGNED │  Перевозчик назначен и уведомлен,
└────┬─────┘  но еще не подтвердил начало работы
     │
     │ Перевозчик подтверждает принятие
     │ (PUT /api/orders/{id}/confirm?carrierId=X)
     │
     ▼
┌─────────────┐
│ IN_PROGRESS │  Перевозчик забрал груз,
└──────┬──────┘  доставка в пути
       │
       │ Перевозчик отмечает доставку
       │ (PUT /api/orders/{id}/complete?carrierId=X)
       │
       ▼
┌─────────────┐
│  COMPLETED  │  Груз доставлен
└──────┬──────┘  Заказчик может оставить отзыв
       │
       ▼
  [АРХИВ / ИСТОРИЯ]
```

## Статусы сущностей

### Статусы заказов
| Статус | Описание | Доступные действия |
|--------|----------|-------------------|
| `NEW` | Заказ создан, ждет предложений | Отмена, создание предложений, поиск |
| `ASSIGNED` | Перевозчик выбран, ожидает подтверждения | Подтверждение перевозчиком, отмена |
| `IN_PROGRESS` | Перевозчик подтвердил, заказ в пути | Завершение доставки |
| `COMPLETED` | Доставка успешно завершена | Оставить отзыв |
| `CANCELLED` | Заказ отменен | Нет (терминальный статус) |

### Статусы предложений (Bids)
| Статус | Описание |
|--------|----------|
| `PENDING` | Предложение отправлено, ждет решения |
| `ACCEPTED` | Заказчик выбрал это предложение |
| `REJECTED` | Предложение отклонено (вручную или автоматически) |

### Статусы тикетов поддержки (Tickets)
| Статус | Описание |
|--------|----------|
| `OPEN` | Тикет создан, ожидает ответа поддержки |
| `IN_PROGRESS` | Поддержка взяла тикет в работу |
| `WAITING` | Поддержка ответила, ожидает реакции пользователя |
| `RESOLVED` | Проблема решена, ожидает закрытия |
| `CLOSED` | Тикет закрыт (терминальный статус) |
