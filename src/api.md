## 1. Пользователи (Users)

### 1.1. Создать пользователя

**POST** `/api/users`

Создает нового пользователя в системе (заказчик, перевозчик или администратор).

**Тело запроса:**
```json
{
  "name": "Иван Петров",
  "email": "ivan@example.com",
  "phone": "+79991234567",
  "role": "CUSTOMER"
}
```

**Параметры тела:**
| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| name | String | ✅ | ФИО пользователя |
| email | String | ✅ | Email (уникальный) |
| phone | String | ✅ | Телефон в формате +7XXXXXXXXXX |
| role | String | ✅ | Роль: `CUSTOMER`, `CARRIER`, `ADMIN` |

**Ответ (201 Created):**
```json
{
  "id": 1,
  "name": "Иван Петров",
  "email": "ivan@example.com",
  "phone": "+79991234567",
  "role": "CUSTOMER",
  "completedOrders": 0,
  "rating": null,
  "createdAt": "2026-09-06T10:00:00"
}
```

**Примеры запросов для разных ролей:**

Заказчик:
```json
{
  "name": "ООО Логистик",
  "email": "logistic@example.com",
  "phone": "+74951234567",
  "role": "CUSTOMER"
}
```

Перевозчик:
```json
{
  "name": "Иван Перевозчиков",
  "email": "ivan.carrier@example.com",
  "phone": "+79161234567",
  "role": "CARRIER"
}
```

Администратор:
```json
{
  "name": "Админ Системы",
  "email": "admin@tms.com",
  "phone": "+74950000000",
  "role": "ADMIN"
}
```

---

### 1.2. Получить всех пользователей

**GET** `/api/users`

Возвращает список всех зарегистрированных пользователей.

**Ответ (200 OK):**
```json
[
  {
    "id": 1,
    "name": "Иван Петров",
    "email": "ivan@example.com",
    "phone": "+79991234567",
    "role": "CUSTOMER",
    "completedOrders": 15,
    "rating": 4.8
  },
  {
    "id": 2,
    "name": "Петр Сидоров",
    "email": "petr@example.com",
    "phone": "+79161234567",
    "role": "CARRIER",
    "completedOrders": 120,
    "rating": 4.9
  }
]
```

---

### 1.3. Получить пользователя по ID

**GET** `/api/users/{id}`

**Параметры пути:**
| Параметр | Тип | Описание |
|----------|-----|----------|
| id | Long | ID пользователя |

**Ответ (200 OK):**
```json
{
  "id": 1,
  "name": "Иван Петров",
  "email": "ivan@example.com",
  "phone": "+79991234567",
  "role": "CUSTOMER",
  "completedOrders": 15,
  "rating": 4.8,
  "createdAt": "2026-01-15T10:30:00"
}
```

**Ответ (404 Not Found):**
```json
{
  "timestamp": "2026-09-06T10:00:00",
  "status": 404,
  "error": "Not Found",
  "message": "Пользователь не найден"
}
```

---

### 1.4. Обновить пользователя

**PUT** `/api/users/{id}`

**Параметры пути:**
| Параметр | Тип | Описание |
|----------|-----|----------|
| id | Long | ID пользователя |

**Тело запроса:**
```json
{
  "name": "Иван Петров (обновлено)",
  "email": "ivan.new@example.com",
  "phone": "+79997654321"
}
```

**Ответ (200 OK):** Обновленный объект пользователя

---

### 1.5. Удалить пользователя

**DELETE** `/api/users/{id}`

**Ответ (204 No Content)**

## 3. Заказы (Orders)

### 3.1. Создать заказ (с автоматическим ML-предсказанием цены)

**POST** `/api/orders`

Создает новый заказ и **автоматически рассчитывает** прогнозируемую стоимость с помощью ML-алгоритма.

**Тело запроса:**
```json
{
  "customerId": 1,
  "fromCity": "Москва",
  "fromAddress": "ул. Ленина, 1",
  "toCity": "Санкт-Петербург",
  "toAddress": "Невский пр., 100",
  "weight": 5.5,
  "categoryId": 1,
  "deadline": "2026-09-15T18:00:00"
}
```

**Параметры тела:**
| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| customerId | Long | ✅ | ID заказчика |
| fromCity | String | ✅ | Город отправления |
| fromAddress | String | ✅ | Точный адрес отправления |
| toCity | String | ✅ | Город назначения |
| toAddress | String | ✅ | Точный адрес назначения |
| weight | BigDecimal | ✅ | Вес груза в тоннах |
| categoryId | Long | ❌ | ID категории груза |
| deadline | LocalDateTime | ✅ | Срок доставки (ISO 8601) |

**Ответ (201 Created):**
```json
{
  "id": 1,
  "fromCity": "Москва",
  "fromAddress": "ул. Ленина, 1",
  "toCity": "Санкт-Петербург",
  "toAddress": "Невский пр., 100",
  "weight": 5.50,
  "deadline": "2026-09-15T18:00:00",
  "status": "NEW",
  "predictedPrice": 22925.00,
  "customer": {
    "id": 1,
    "name": "Иван Петров",
    "email": "ivan@example.com"
  },
  "carrier": null,
  "category": {
    "id": 1,
    "name": "Продукты питания",
    "requiresSpecialPermit": true
  },
  "createdAt": "2026-09-06T10:00:00"
}
```

**Важно:** Поле `predictedPrice` заполняется **автоматически** ML-алгоритмом при создании заказа.

---

### 3.2. Получить заказ по ID

**Ответ (200 OK):**
```json
{
  "id": 1,
  "fromCity": "Москва",

  "toCity": "Санкт-Петербург",
  "toAddress": "Невский пр., 100",
  "weight": 5.50,

  "status": "NEW",
  "predictedPrice": 22925.00,
  "customer": {
    "id": 1,
    "name": "Иван Петров"
  },
  "carrier": null,
  "category": {
    "id": 1,
    "name": "Продукты питания"
  }
}
```

---

### 3.3. Получить все заказы

**GET** `/api/orders`

Возвращает все заказы в системе (удобно для администратора).

**Ответ (200 OK):** Массив объектов Order

---

### 3.4. Получить заказы заказчика

**GET** `/api/orders/customer/{customerId}`

**Ответ (200 OK):** Массив заказов конкретного заказчика

---

### 3.5. Получить заказы перевозчика

**GET** `/api/orders/carrier/{carrierId}`

**Ответ (200 OK):** Массив заказов конкретного перевозчика

---

### 3.6. Отменить заказ

**PUT** `/api/orders/{id}/cancel`

Отменяет заказ. Доступно заказчику или администратору.

**Ответ (200 OK):**
```json
{
  "id": 1,
  "status": "CANCELLED",
  ...
}
```

**Ошибки:**
- `400 Bad Request`: Нельзя отменить завершенный заказ

---

### 3.7. Подтвердить заказ (перевозчик принимает)

**PUT** `/api/orders/{id}/confirm?carrierId=2`

Перевозчик подтверждает принятие заказа. Статус меняется с `NEW` на `ASSIGNED`.

**Параметры запроса:**
| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| carrierId | Long | ✅ | ID перевозчика |

**Ответ (200 OK):**
```json
{
  "id": 1,
  "status": "ASSIGNED",
  "carrier": {
    "id": 2,
    "name": "Петр Сидоров"
  },
  ...
}
```

**Ошибки:**
- `400 Bad Request`: Заказ должен быть в статусе NEW

---

### 3.8. Завершить заказ (доставка выполнена)

**PUT** `/api/orders/{id}/complete?carrierId=2`

Перевозчик отмечает заказ как доставленный. Статус меняется на `COMPLETED`.

**Параметры запроса:**
| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| carrierId | Long | ✅ | ID перевозчика |

**Ответ (200 OK):**
```json
{
  "id": 1,
  "status": "COMPLETED",
  ...
}
```

**Ошибки:**
- `400 Bad Request`: Заказ должен быть в статусе IN_PROGRESS

---

### 3.9. Обновить заказ

**PUT** `/api/orders/{id}`

Обновляет данные заказа. Доступно только администратору.

**Параметры запроса:**
| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| adminId | Long | ✅ | ID администратора (query param) |

**Тело запроса:** Аналогично созданию заказа

**Ответ (200 OK):** Обновленный объект заказа

---

### 3.10. Удалить заказ

**DELETE** `/api/orders/{id}?adminId=1`

Удаляет заказ. Доступно только администратору.

**Параметры запроса:**
| Параметр | Тип | Обязательный | Описание |
|----------|-----|--------------|----------|
| adminId | Long | ✅ | ID администратора |

**Ответ (204 No Content)**

**Ошибки:**
- `400 Bad Request`: Нельзя удалить активный или завершенный заказ

---

### 3.11. История заказов заказчика

**GET** `/api/orders/customer/{customerId}/history`

Возвращает завершенные и отмененные заказы заказчика.

**Ответ (200 OK):** Массив заказов со статусами `COMPLETED` и `CANCELLED`

---

### 3.12. Активные заказы заказчика

**GET** `/api/orders/customer/{customerId}/active`

Возвращает активные заказы (статусы: `NEW`, `ASSIGNED`, `IN_PROGRESS`).

**Ответ (200 OK):** Массив активных заказов

---

### 3.13. История заказов перевозчика

**GET** `/api/orders/carrier/{carrierId}/history`

**Ответ (200 OK):** Массив завершенных и отмененных заказов

---

### 3.14. Активные заказы перевозчика

**GET** `/api/orders/carrier/{carrierId}/active`

**Ответ (200 OK):** Массив активных заказов перевозчика

## 4. Предложения перевозчиков (Bids)

### 4.1. Создать предложение

**POST** `/api/bids`

Перевозчик создает предложение по заказу.

**Тело запроса:**
```json
{
  "orderId": 1,
  "carrierId": 2,
  "price": 20000.00,
  "estimatedDays": 3,
  "comment": "Готов доставить за 3 дня, есть опыт перевозки продуктов"
}
```

**Параметры тела:**
| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| orderId | Long | ✅ | ID заказа |
| carrierId | Long | ✅ | ID перевозчика |
| price | BigDecimal | ✅ | Предлагаемая цена |
| estimatedDays | Integer | ✅ | Ожидаемое количество дней |
| comment | String | ❌ | Комментарий перевозчика |

**Ответ (201 Created):**
```json
{
  "id": 1,
  "orderId": 1,
  "carrierId": 2,
  "price": 20000.00,
  "estimatedDays": 3,
  "status": "PENDING",
  "comment": "Готов доставить за 3 дня, есть опыт перевозки продуктов",
  "createdAt": "2026-09-06T10:30:00"
}
```

---

### 4.2. Получить все предложения для заказа

**GET** `/api/bids/order/{orderId}`

Возвращает все предложения перевозчиков для конкретного заказа (без ранжирования).

**Ответ (200 OK):**

```json
  },
  {
    "id": 2,
    "orderId": 1,
    "carrier": {
      "id": 3,
      "name": "Петр Быстрый"
    },
    "price": 23500.00,
    "estimatedDays": 2,
    "status": "PENDING",
    "comment": "Доставлю за 2 дня"
  }
]
```

**Ответ (200 OK):**

### 4.4. Принять предложение

**PUT** `/api/bids/{bidId}/accept`

Заказчик принимает предложение перевозчика. Заказ переходит в статус `ASSIGNED`.

**Ответ (200 OK):**
```json
{
  "id": 1,
  "status": "ASSIGNED",
  "carrier": {
```

## 11. Сценарии использования

### Сценарий 1: Заказчик создает заказ

**Шаги:**
1. `POST /api/predictions/price` - узнать примерную цену
2. `POST /api/orders` - создать заказ (цена сохранится автоматически)
3. `GET /api/orders/{id}` - проверить заказ

**Пример:**
```bash
# 1. Узнаем цену
curl -X POST http://localhost:8080/api/predictions/price \
  -H "Content-Type: application/json" \
  -d '{
    "fromCity": "Москва",
    "toCity": "Санкт-Петербург",
    "weight": 5.5,
    "categoryId": 1,
    "deadline": "2026-09-15T18:00:00"
  }'

# 2. Создаем заказ
curl -X POST http://localhost:8080/api/orders \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": 1,
    "fromCity": "Москва",
    "fromAddress": "ул. Ленина, 1",
    "toCity": "Санкт-Петербург",
    "toAddress": "Невский пр., 100",
    "weight": 5.5,
    "categoryId": 1,
    "deadline": "2026-09-15T18:00:00"
  }'

# 3. Проверяем заказ
curl http://localhost:8080/api/orders/1
```

---

### Сценарий 2: Перевозчик ищет заказы и делает предложение

**Шаги:**
1. `GET /api/orders/search` - найти подходящие заказы
2. `POST /api/bids` - сделать предложение
3. `GET /api/bids/orders/recommendations?orderId=1` - увидеть свой рейтинг

**Пример:**
```bash
# 1. Ищем заказы
curl "http://localhost:8080/api/orders/search?fromCity=Москва&toCity=Санкт-Петербург"

# 2. Делаем предложение
curl -X POST http://localhost:8080/api/bids \
  -H "Content-Type: application/json" \
  -d '{
    "orderId": 1,
    "carrierId": 2,
    "price": 20000.00,
    "estimatedDays": 3,
    "comment": "Готов доставить за 3 дня"
  }'

# 3. Смотрим рейтинг
curl "http://localhost:8080/api/bids/orders/recommendations?orderId=1"
```

---

### Сценарий 3: Заказчик выбирает перевозчика

**Шаги:**
1. `GET /api/bids/order/{orderId}` - посмотреть все предложения
2. `GET /api/predictions/orders/{orderId}/compare-bids` - сравнить с ML-прогнозом
3. `PUT /api/bids/{bidId}/accept` - принять лучшее предложение

**Пример:**
```bash
# 1. Смотрим все предложения
curl http://localhost:8080/api/bids/order/1

# 2. Сравниваем с прогнозом
curl http://localhost:8080/api/predictions/orders/1/compare-bids

# 3. Принимаем предложение
curl -X PUT http://localhost:8080/api/bids/1/accept
```

---

### Сценарий 4: Полный цикл доставки

**Шаги:**
1. Заказчик создает заказ → статус `NEW`
2. Перевозчики делают предложения
3. Заказчик принимает предложение → статус `ASSIGNED`
4. Перевозчик подтверждает принятие → статус `IN_PROGRESS`
5. Перевозчик завершает доставку → статус `COMPLETED`

## 12. Архитектура и особенности

### 12.1. ML-модуль

**Тип модели:** Эвристическая многофакторная система (rule-based)

**Факторы расчета:**
1. **Расстояние** - формула гаверсинусов с динамическим коэффициентом
2. **Вес груза** - +5% за каждую тонну
3. **Срочность** - до +100% для очень срочных заказов
4. **Категория груза** - +20-40% для специальных грузов

**Преимущества:**
- ✅ Полная объяснимость (Explainable AI)
- ✅ Мгновенный отклик (< 10ms)
- ✅ Не требует обучения на данных
- ✅ Архитектура готова к переходу на настоящий ML

---

### 12.2. Безопасность

- Пароли хранятся в переменных окружения
- Конфигурация разделена по профилям (локальный/продакшен)
- Репозиторий приватный, чувствительные данные в `.gitignore`
- Используются переменные окружения Railway для продакшена

---

### 12.3. Производительность

- Оптимизированные SQL-запросы с `LEFT JOIN FETCH`
- Пул соединений HikariCP (макс. 10 соединений)
- Кэширование на уровне Hibernate
- Динамический расчет расстояний (без внешних API)
